# Проверка полного пользовательского сценария

`make smoke-e2e` запускает воспроизводимую проверку API для синтетического Solidity-контракта. Это интеграционная проверка с заглушками через FastAPI `TestClient`, а не браузерный или полная сквозная проверка.

## Запуск

Подготовьте зависимости для сборки без сети и локальное окружение по [инструкции установки](./setup.md), затем выполните:

```bash
make smoke-e2e
```

Команда поднимает PostgreSQL и Redis с ожиданием успешной проверки состояния, затем запускает тест во временном серверном контейнере. Серверный тест использует отдельную БД `chainwise_test`; он не очищает рабочую БД. В конце тест удаляет синтетический контракт и оба тестовых аккаунта через API. `make down` остановит зависимости после проверки.

Установленный Node.js нужен для проверки пояснения к оценке риска в интерфейсе. Ни `OPENAI_API_KEY`, ни реальные пользовательские данные не требуются.

## Что проверяется

- регистрация и вход двух временных пользователей;
- отказ на повреждённом ZIP (`400`);
- загрузка небольшого `SmokeDemo.sol` (`202`) и опрос статуса до `ready` или явной ошибки;
- предел ожидания: не более 20 запросов статуса, не более 5 секунд и пауза 50 мс; автоматических повторных запусков анализа нет;
- найденные проблемы, оценка `B` и источник оценки `heuristic`;
- `404` при чтении чужого контракта;
- исходник, контролируемый вопрос и непустые цитаты с путём файла и диапазоном строк, проверенным относительно загруженного текста;
- PDF с `application/pdf`, `%PDF-` заголовком и завершающим `%%EOF`;
- удаление контракта и тестовых аккаунтов после чата.

API, SQLAlchemy/PostgreSQL, ограничения Redis, обработчик загрузки, синхронное выполнение задачи Celery, маршруты исходников, найденных проблем, чата и отчёта выполняются настоящим кодом. Компилятор, Slither, индексирование и поиск Qdrant и языковая модель заменены детерминированными заглушками. Текст предупреждения в интерфейсе проверяется отдельным тестом Node.js.

Серверное задание автоматической проверки запускает `pytest tests/`, включая `test_smoke_e2e.py`. Команда `make smoke-e2e` также проверяет текст предупреждения в интерфейсе.

## Проверка настоящих интеграций

Тест `backend/tests/test_live_e2e.py` выполняет тот же сценарий с настоящими solc, Slither, FastEmbed и Qdrant. Генерация текста языковой моделью по умолчанию заменена заглушкой:

```bash
make deps                    # заранее подготавливает разрешённый solc и MiniLM
make up
make health
docker compose exec -T backend env \
  CHAINWISE_LIVE_E2E=1 \
  CHAINWISE_LIVE_E2E_MOCK_LLM=1 \
  python -m pytest tests/test_live_e2e.py -v
```

Тест загружает синтетический `LiveDemo.sol`, выполняет компиляцию, Slither, векторизацию и поиск Qdrant. Он проверяет найденные проблемы, оценку риска, отказ чужому пользователю, цитаты и PDF. Slither должен обнаружить проблему `immutable-states`. Повреждённый ZIP проверяется как отрицательный сценарий.

Celery исполняет задачу синхронно. Опрос статуса ограничен 120 секундами, HTTP-запросы анализатора — 20 секундами и одним коротким повтором при перегрузке, клиент Qdrant — 10 секундами. Блок `finally` удаляет контракт и оба временных аккаунта, затем проверяет, что они недоступны. Не запускайте тест против рабочей базы.

Для одного настоящего вызова языковой модели задайте в `.env` ключ выбранного сервиса, совместимого с OpenAI, и удалите `CHAINWISE_LIVE_E2E_MOCK_LLM=1` из команды. Тест отправляет один вопрос. При использовании заглушки векторизация, поиск и цитаты остаются настоящими; заменяется только генерация текста.

Ручную проверку интерфейса можно выполнить через `http://localhost:3001`. Она не входит в автоматические проверки. GitHub Actions не подготавливает solc и модель FastEmbed, поэтому тест настоящих интеграций по умолчанию пропускается. Выполненные прогоны и их условия зафиксированы в [результатах проверок](./verification-results.md).
